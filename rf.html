Random Forest

Scratch NumPy ~15 min read Expect: RF class + variance/OOB theory

A single deep tree memorizes noise (high variance). Random Forest fixes this by training many trees on bootstrap samples and letting each split see only a random subset of features, then majority-voting.

Remember just these 3 things
  1. Bootstrap: each tree trains on \(n\) rows drawn with replacement → ~63.2% unique rows, ~36.8% left out (OOB).
  2. Random features: each split looks at only \(m=\sqrt{p}\) features (max_features="sqrt") → trees become less alike.
  3. Predict: every tree votes, take the majority. Variance \(= \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2\).

1. Plain Intuition

Two sources of randomness = decorrelated trees
  1. Row randomness (Bootstrap): Draw \(n\) samples with replacement for each tree.
  2. Column randomness (Feature subsampling): At every split, look only at \(m < p\) randomly picked features (default \(m = \lfloor\sqrt{p}\rfloor\) for classification).

Why both? Without column subsampling (plain Bagging), one dominant feature makes every tree look similar at the top—so averaging doesn't reduce variance as much.

2. Formulas You Must Know

OOB Share, Ensemble Variance & Feature Subsets

1. Out-of-Bag (OOB) Probability: Probability sample \(i\) is never picked in \(n\) bootstrap draws:

\[P(\text{OOB}) = \left(1 - \frac{1}{n}\right)^n \xrightarrow{n\to\infty} e^{-1} \approx 0.368 \quad (\approx 36.8\%)\]

So each tree leaves ~36.8% of data unseen—giving a built-in validation estimate (OOB error \(\approx\) CV/Test error).

2. Why Correlated Bagging Hits a Wall (Variance of Average of \(B\) Trees):

\[\text{Var}\!\left(\frac{1}{B}\sum_{b=1}^{B} T_b\right) = \rho\sigma^2 + \frac{1 - \rho}{B}\sigma^2\]

As \(B\to\infty\), the second term vanishes, leaving \(\rho\sigma^2\). Subsampling \(m\) features lowers pairwise tree correlation \(\rho\)!

3. Rule-of-Thumb Split Size: \(m = \sqrt{p}\) (Classification), \(m \approx p/3\) (Regression).

3. Pen-and-Paper Code (Lab 7)

Lab 7 · Bootstrap, Majority Vote & RandomForestScratch
def bootstrap_indices(n_samples, rng):
    return rng.choice(n_samples, size=n_samples, replace=True)

def bootstrap_sample(X, y, rng):
    indices = bootstrap_indices(len(X), rng)
    return X[indices], y[indices], indices

def majority_vote(predictions):
    # predictions has shape (n_trees, n_samples)
    result = []
    for sample_votes in predictions.T:
        values, counts = np.unique(sample_votes, return_counts=True)
        result.append(values[np.argmax(counts)])
    return np.array(result)

class RandomForestScratch:
    def __init__(self, n_trees=30, max_depth=5, max_features="sqrt",
                 criterion="gini", random_state=42):
        self.n_trees = n_trees
        self.max_depth = max_depth
        self.max_features = max_features
        self.criterion = criterion
        self.random_state = random_state
        self.trees = []
        self.bootstrap_indices_ = []

    def fit(self, X, y):
        X, y = np.asarray(X), np.asarray(y)
        rng = np.random.default_rng(self.random_state)
        self.trees, self.bootstrap_indices_ = [], []
        for _ in range(self.n_trees):
            X_boot, y_boot, indices = bootstrap_sample(X, y, rng)
            tree = DecisionTreeScratch(
                max_depth=self.max_depth,
                max_features=self.max_features,
                criterion=self.criterion,
                random_state=int(rng.integers(0, 1_000_000)),
            )
            tree.fit(X_boot, y_boot)
            self.trees.append(tree)
            self.bootstrap_indices_.append(indices)
        return self

    def predict_all_trees(self, X):
        return np.array([tree.predict(X) for tree in self.trees])

    def predict(self, X):
        return majority_vote(self.predict_all_trees(X))
1-Minute Memory Hook

RandomForestScratch.fit = loop n_trees times: bootstrap_sample(replace=True) → create DecisionTreeScratch(max_features="sqrt") → tree.fit(X_boot, y_boot). Predict = stack all tree predictions and take column-wise majority_vote.

4. Single Tree vs Bagging vs Random Forest

MethodBootstrap rows?Random features per split?Result
Single Decision TreeNoNoLow bias, high variance
BaggingYesNo (\(m = p\))Lower variance, but trees still correlated
Random ForestYesYes (\(m = \sqrt{p}\))Lowest variance: trees decorrelated (\(\downarrow \rho\))

5. Practice + Self-Checks

Check 1Does increasing n_trees in Random Forest cause overfitting?

No. More trees only make the average more stable (variance falls towards \(\rho\sigma^2\)); they just cost more time.

Check 2In Lab 7, how did Gini vs Entropy compare on the binary Iris split?

Single DT and RF (n_trees=30, max_depth=5, max_features="sqrt") both got 0.80 test accuracy, and switching to Entropy kept both at 0.80, because Gini and Entropy rank splits almost identically.
